# 全流程走演——从原始轨迹到信用分配

> 任务：**heat some tomato and put it on the table**（ALFWorld 环境）
>
> 跑 4 条轨迹，先拿一条正常成功的走完整套流程。

---

# 阶段 A · 在线压缩

## 在干什么

agent 每走一步，问模型一次"这任务能成吗？"→ 把握值 V_t。

前后两步的把握差 = 跳幅 Δ_t。**跳得猛 = 这一步重要。**

固定 token 预算内，重要的步保留原文，不重要的压掉。

## 轨迹（10 步，原文共 136 token）

```
步0  柜台上看到苹果、面包、黄油刀、杯子、叉子、番茄       （30 token）
步1  你从柜台上拿起了番茄                                （12 token）
步2  微波炉是关着的                                       （6 token）
步3  你打开微波炉，里面是空的                              （12 token）
步4  你把番茄放进了微波炉                                 （10 token）
步5  你关上了微波炉                                       （6 token）
步6  你用微波炉加热了番茄                                 （10 token）
步7  你从微波炉里取出了番茄                               （12 token）
步8  餐桌上看到盐瓶、胡椒瓶、肥皂瓶、铲子                  （28 token）
步9  你把番茄放在了餐桌上                                 （10 token）

结果：成功 ✅  R = 1.0
```

## 每步问一次"能成吗"

| 步 | 内容 | V_t | Δ_t | 跳幅解读 |
|---|---|---|---|---|
| — | （先验起点） | 0.50 | — | |
| 0 | 柜台杂物 | 0.35 | 0.15 | 开局，一切都还没开始 |
| **1** | **拿番茄** | **0.55** | **0.20** | 👈 跳最猛！拿到目标物品了 |
| 2 | 微波炉关门 | 0.56 | 0.01 | 几乎没跳 = 废话 |
| 3 | 打开微波炉 | 0.58 | 0.02 | 微跳 |
| **4** | **番茄放微波炉** | **0.75** | **0.17** | 👈 第二跳！放入微波炉 |
| 5 | 关上微波炉 | 0.76 | 0.01 | 废话 |
| **6** | **加热番茄** | **0.90** | **0.14** | 👈 第三跳！加热成功 |
| 7 | 取出番茄 | 0.92 | 0.02 | 微跳 |
| 8 | 桌上杂物 | 0.90 | 0.02 | 还跌了——与任务无关 |
| **9** | **番茄放桌上** | **0.98** | **0.08** | 👈 收官跳 |

**两步废话**：步2（关门）Δ=0.01，步5（关门）Δ=0.01——做了等于没做，对"能不能成"的影响几乎为零。

**四步关键**：步1（拿番茄）、步4（入炉）、步6（加热）、步9（放桌上）——每一步都让把握明显上涨。

## 回溯压缩（预算=40，很紧）

步9 完成后，回头看步0~8。所有步的起点 = MERGE，按"性价比 = 跳幅÷长度"从高到低，逐个试着升档：

排队：

```
性价比排序：步1(0.017) > 步4(0.017) > 步6(0.014) > 步0(0.005)
           > 步3(0.002) > 步7(0.002) > 步5(0.002) > 步2(0.002) > 步8(0.001)
```

逐轮升档（步9 当前步 → FULL，10 token，不占预算）：

```
① 步1 试 FULL（12 token）：预算够 ✅ → 升 FULL，剩 28
② 步4 试 FULL（10 token）：预算够 ✅ → 升 FULL，剩 18
③ 步6 试 FULL（10 token）：预算够 ✅ → 升 FULL，剩 8
④ 步0 试 FULL（30 token）：不够 ❌
   步0 试 SUMM（~12 token）：不够 ❌  → 保持 MERGE
⑤ 步3 试 SUMM（~5 token）：预算够 ✅ → 升 SUMM，剩 3
⑥ 步7 试 SUMM：不够 ❌ → 保持 MERGE
⑦ 步5：Δ=0.01 = min_jump，勉强进入队伍，但预算剩 3，SUMM 也不够 → MERGE
⑧ 步2：Δ=0.01，预算不够 → MERGE
⑨ 步8：Δ=0.02，但原文 28 token 太大，早早被排到末尾，预算已花光 → MERGE
```

## 最终压缩结果（预算 40）

```
[FULL]  步1  你从柜台上拿起了番茄                  c=1.0
[SUMM]  步3  打开微波炉，里面是空的                  c=0.6
[FULL]  步4  你把番茄放进了微波炉                   c=1.0
[FULL]  步6  你用微波炉加热了番茄                   c=1.0
[FULL]  步9  你把番茄放在了餐桌上                   c=1.0
[MERGE] (此处 5 步例行操作已折叠)   ← 步0/步2/步5/步7/步8 五合一
                                          c=0.3
```

> 原文 136 token → 压缩后约 38 token，缩小了 3.6 倍。

**为什么步 0（Δ=0.15，跳幅不小）也被折叠了？** 因为它原文 30 token 太长了，性价比（0.15/30=0.005）远不如短句。同样 30 个 token 的预算，可以保住步4+步6+步1 三句关键短句，而不是一句啰嗦的开局描述。

**为什么跳幅≈0.01 的废话彻底变成了 MERGE 而不是 SUMM？** 因为预算紧到只剩 3 个 token，SUMM 一句话最少也得 4~5 个 token，塞不进了。如果预算松到 90，它们还能拿 SUMM；预算一紧，直接折叠。

# 阶段 B · 信用分配

## 在干什么

阶段 A 说了"这一步重不重要"。但没说"这一步做得好不好"——"拿苹果"跳幅也大（agent 以为自己对了），但它是错的。

区分对错不能靠自己，得跨轨迹比：**和你处境相似的人做了什么、结果怎么样。**

## 四条轨迹

| 轨迹 | 步1拿了什么 | 后续 | 最终 | R |
|---|---|---|---|---|
| **A** | 拿了番茄 | 加热、放桌上 | ✅ | 1.0 |
| **B** | 拿了番茄 | 加热、放桌上 | ✅ | 1.0 |
| **C** | **拿了苹果** | 加热苹果、放桌上 | ❌ | 0.0 |
| **D** | 拿了番茄 | 加热、放桌上 | ✅ | 1.0 |

## 流程三步

### ① 每步编码成 phi（一个 4096 维的数字向量）

phi = 把 **走到那一步时的压缩 memory 全文** 喂进模型，取最后一个 token 的隐状态。

两个 phi 的余弦相似度越高 → 两个处境越像。

C步1（拿苹果）的 memory："柜台上苹果面包番茄… 你拿起了**苹果**"。A步1（拿番茄）的 memory："柜台上苹果面包番茄… 你拿起了**番茄**"。

整段 memory 只差**一个词**，其余 30+ token 一模一样 → phi 几乎重合 → 相似度约 0.96。

### ② 软分组：phi 越像，权重越高

用公式把相似度 S 变成权重 w：

```
w = exp( (S − 1) / τ )
```

- S = 余弦相似度（1 = 完全一样，0 = 无关）
- τ = 敏感度（默认 0.05），τ 越小越"翻脸"

| S | (S−1)/0.05 | 权重 | 相当于在说 |
|---|---|---|---|
| 1.0（一模一样） | 0 | 1.00 | "你是我自己人" |
| 0.95（差一点） | −1.0 | 0.37 | "听听你的意见" |
| 0.85（差不少） | −3.0 | 0.05 | "基本不信你" |
| 0.6（不相关） | −8.0 | ≈0 | "你是谁我不认识" |

A1/B1/C1/D1 四个 phi 高度相似（只差一个词），算出来的权重矩阵（行归一化后）：

```
        A1      B1      C1      D1
A1       0     0.42    0.18    0.40
B1     0.39      0     0.20    0.41
C1     0.35    0.38      0     0.27
D1     0.39    0.42    0.19      0
```

C1 虽然拿了苹果，但处境和 A1/B1/D1 高度相似 → **被拉进了同一个比较组。**

### ③ 算优势 A = Q̂ − V̂

- **V̂** = 邻居回报的加权平均。"这个处境下，平均能拿多少分？"
- **Q̂** = 和你做了**同一个动作**的邻居的平均回报。"做这个动作的人，平均能拿多少分？"
- **A** = Q̂ − V̂。"你做这件事，比平均水平好多少？"

```
A > 0  → 好动作，加分
A ≈ 0  → 中性，无所谓
A < 0  → 坏动作，扣分
```

---

## 三条代表性步骤的计算

### C 步1（拿苹果）🔴

邻居：A1(1.0) + B1(1.0) + D1(1.0)。

**V̂ ≈ 1.0**。"在柜台前看到番茄，大家基本都成功了。"

**Q̂("拿苹果")** = 只有 C 做了 → 回报 0.0 → Q̂ = 0。

**A = 0 − 1 = −1.00。**"在柜台前拿苹果的人，全失败了。别做这件事。"

---

### A 步1（拿番茄）

同样的邻居，V̂ ≈ 1.0。

**Q̂("拿番茄")** = A1(1.0) + B1(1.0) + D1(1.0) → Q̂ ≈ 1.0。

**A = 1.0 − 1.0 = 0。**"拿番茄是理所当然的，不加分不扣分。"

---

### A 步4（番茄放进微波炉）🟢

邻居：B4(1.0) + D4(1.0) + C4(0.0, 放的苹果)。

**V̂ ≈ 0.80。**"走到微波炉前的人，不是谁都立刻做对了选择。"

**Q̂("放番茄入微波炉")** = A4(1.0) + B4(1.0) + D4(1.0) → Q̂ ≈ 1.0。

**A = 1.0 − 0.80 = +0.20。**"把番茄放进去是一个好动作——不是每个人都做了，但做了的都成了。"

---

## 最终：两条轨迹完整对照

| 步 | 轨迹 A（✅成功） | A值 | | 轨迹 C（❌失败） | A值 |
|---|---|---|---|---|---|
| 0 | 柜台杂物 | 0 | | 柜台杂物 | 0 |
| **1** | **拿番茄** | **0** | | **拿苹果** | **−1.00** 🔴 |
| 2 | 微波炉关门 | 0 | | 微波炉关门 | −0.10 |
| 3 | 打开微波炉 | 0 | | 打开微波炉 | −0.10 |
| **4** | **番茄放微波炉** | **+0.20** 🟢 | | **苹果放微波炉** | **−0.80** 🔴 |
| 5 | 关上微波炉 | 0 | | 关上微波炉 | −0.10 |
| **6** | **加热番茄** | **+0.15** 🟢 | | **加热苹果** | **−0.85** 🔴 |
| 7 | 取出番茄 | 0 | | 取出苹果 | −0.10 |
| 8 | 桌上杂物 | 0 | | 桌上杂物 | −0.10 |
| **9** | **番茄放桌上** | **+0.10** 🟢 | | **苹果放桌上** | **−0.95** 🔴 |

**两类负分**：

- **直接错误步**（C1拿苹果/C4放苹果/C6加热苹果/C9放苹果）→ A 大幅为负（−0.80 ~ −1.00）。动作本身是错的。
- **连带负分**（C2/C3/C5/C7/C8）→ A 微负（−0.10）。动作本身没错，但因为前面已经走错了路，整条轨迹注定失败——这些步跟着"沾锅"。

## 用来更新 agent

| 效果 | 例子 | A |
|---|---|---|
| **强化好动作** | "放番茄入微波炉" / "加热番茄" | +0.15 ~ +0.20 |
| **狠罚坏动作** | "拿苹果" / "加热苹果" | −0.80 ~ −1.00 |
| **废话不学** | "微波炉关着" / "关上门" | ≈ 0 |
| **微调方向** | 拿错东西后的整条路径 | −0.05 ~ −0.10 |

**被 MERGE 的那些步呢？** 它们照样参与信用分配——phi 用的是当时的压缩 memory（那时候它还是 FULL），不受后来被折叠的影响。只是作为别人参照物时可信度打三折（c=0.3）。

# 全流程一览

```
阶段A（在线·每步）                      阶段B（离线·批量）
─────────────────                      ─────────────────
obs → 探针"能成吗？"                    所有轨迹的 memoryₜ + aₜ + R + cₜ
        ↓                                       ↓
    跳幅 Δₜ                             ⑤ 编码 phi（每步一个向量）
        ↓                                       ↓
 贪心分档位（FULL/SUMM/MERGE）            ⑥ 软分组（phi像→权重高）
        ↓                                       ↓
 压缩 memoryₜ                             ⑦ 算 V̂ = Σ w×R
 保真度 cₜ                                ⑧ 算 Q̂ = 同动作邻居平均
        ↓                                       ↓
 agent 看 memoryₜ 决策                    ⑨ A = Q̂ − V̂
                                                ↓
                                           GRPO 更新 actor
```
