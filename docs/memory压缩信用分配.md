## 1. 问题：为什么非压不可

### 1.1 场景

agentic RL，单智能体多轮交互，**稀疏轨迹奖励**。需要把终局回报拆到每一步（credit assignment, CA）。主流范式是**分组式 CA**：把处于相同处境的步凑成组，组内比不同动作的回报 → 得到每步优势（GiGPO / HGPO / BiPACE / GraphGPO 一系）。

### 1.2 两条动机

**动机一 · token 硬上限（必需）**。LLM agent 的 context 有硬上限，长程历史必然超限。压缩不是"让算法更好学"，而是**物理上非压不可**。既然是因为硬上限，压缩就必须是**固定 token 上限**——固定比例下 token 仍随轨迹线性增长，照样超限。

**动机二 · 冗余主动干扰信用分配（有益）** ★论文卖点。全历史的无关内容不只占地方，还会淹没信用信号。已有间接证据：合成诊断中压缩后的 sep-AUC 从 0.52~0.67 提升到 0.93；MemoPilot 发现 Full History 的成绩反而低于 selective memory。

注意 Ni 2023 已证明 Transformer 靠大 context 能解到 1500 步的记忆任务——"记得住"不是瓶颈。但**记得住 ≠ 分得对信用**。在流水账里判准哪一步立了功，才是本方法要解决的问题。

### 1.3 空档

已读的 memory 压缩论文目标清一色是"压完还能检索/答题/拿任务奖励"。**没有一篇是为了"压完还能把信用分对"去压的。** BiPACE 在结论中明确把"compress history into a memory module"列为 future work；HGPO 承认压缩后层级分组变得 intractable。

## 2. 方法概览：两个阶段

压缩在 **rollout 内部**完成——agent 决策时看到的就必须是压缩后的 memory，否则照样超 context。跑完之后再跨轨迹做信用分配。

```
阶段A（在线·每步）                         阶段B（离线·批量）
─────────────────                         ─────────────────
obs → 把握信号"能成吗？"                     所有轨迹的 memoryₜ + aₜ + R + cₜ
        ↓                                          ↓
    跳幅 Δₜ                                编码 phi（每步一个向量）
        ↓                                          ↓
 贪心分三档（FULL/SUMM/MERGE）               软分组（phi 像 → 权重高）
        ↓                                          ↓
 压缩 memoryₜ                                保真度加权（压得粗的降权）
 保真度 cₜ                                           ↓
        ↓                                  算优势 A = Q̂(s,a) − V̂(s)
 agent 用 memoryₜ 决策                              ↓
                                               GRPO 更新 actor
```

**两个阶段的接口**：保真度 `cₜ`。阶段 A 压缩时顺手产出，阶段 B 用来给不可靠邻居降权。零额外成本。

## 3. 阶段 A：在线压缩

### 3.1 把握信号：两种路线

核心问题：每走一步，我们需要一个"把握值" V_t——模型觉得这任务能成吗？前后两步的把握差 = 跳幅 Δ_t。跳得猛 = 这步重要。

**路线一：ValueProbe（单独问一次）**

每走一步，问模型"这个任务能成功吗？是/否"，但不让它生成文字——只读最后位置的 logits，看"是/否"两个 token 的相对概率：

```
V_t = P(是) / (P(是) + P(否))
```

**为什么比让它生成好**：一次 forward 不 decode，比逐字生成快一个量级；只在"是/否"之间归一化，排除其他 token 的干扰；得到连续值（0.70 而非硬的是/否），跳幅正是靠这个连续性算出来的。

- V_t 是模型的主观判断，不是真实概率。但方法只用跳幅（相对变化），不用绝对值。只要能分出"这步比那步跳得多"就够。

**路线二：∆Belief（从决策 forward 里顺手读，零额外成本）**

以上 ValueProbe 需要单独跑一次 forward——复用 actor 的 KV cache 后仍占决策耗时的 ~13.9%。∆Belief-RL（Auzina et al., ICML 2026）给出了一个更省的做法：

agent 做决策时的 forward pass 里，模型内部已经在比较候选动作的概率。多拼几个 token（如"正确答案是："），读候选答案的 log-probability，就能得到：

```
b_t = P(正确答案 | 前 t 步记忆)
```

**没有第二次 forward。** 多拼的几个 token 混在同一次 forward 里一并算了 → 额外成本 ~1%。

∆Belief 的跳幅公式（原论文用对数比）：

```
∆Belief_t = |log(b_t) − log(b_{t-1})|
```

初始值为均匀先验（4 个颜色 → b_{-1} = 0.25）。对数比的好处：把"从蒙到有线索"这段放大——早期线索的获取才是压缩该保留的，后期微调不值钱。

#### 一张图对比两种路线

```
ValueProbe（两次 forward）:
  ┌──────────────┐    ┌──────────────┐
  │ Forward ①    │    │ Forward ②    │
  │ agent 决策    │    │ 探针"能成吗"  │
  │              │    │              │
  │ memory 部分   │───→│ KV cache 复用 │   13.9% 额外
  │ + 决策prompt  │    │ + 探针prompt  │
  └──────────────┘    └──────────────┘
                            ↓
                      V_t = P(是)

∆Belief（一次 forward）:
  ┌──────────────────────────────┐
  │ Forward ①（唯一一次）         │
  │ agent 决策 + 信念一起出       │
  │                              │
  │ memory + 决策prompt           │   ~1% 额外
  │ + "答案是:" + 候选token       │
  └──────────────────────────────┘
           ↓                ↓
      采样动作          b_t = P(正确答案)
```

#### 在钥匙-门合成任务上的验证

| 信号 | AUC | top-1 命中率 |
|---|---|---|
| ValueProbe·success | **0.905** | 88.9% |
| ∆Belief·abs | **0.839** | **100.0%** |
| 对照·random | 0.432 | 5.6% |
| 对照·length | 0.938 | 100.0% |

∆Belief 的 AUC（0.839）略低于 ValueProbe（0.905），但 **top-1 命中率 100%**——从不认错最重要的一步。对压缩来说，关键步不掉比整体排序重要。

### 3.2 为什么 ∆Belief 不能替代 ValueProbe

∆Belief 虽然近乎免费，但有一个硬性前提：**"正确答案"必须可枚举**。

回到钥匙-门任务：终点有一扇锁着的门，agent 要选钥匙颜色——暗红色、黄铜色、深绿色、银白色。四个候选是确定的，所以每一步都能算 b_t = P("暗红色"|记忆)。当告示说"今天能开门的，是暗红色的钥匙"，b_t 从 0.25 跳到 0.9，跳幅巨大 → 告示步被保留。

但真实任务 ALFWorld 拿番茄：agent 的动作空间是开放的——"从柜台拿起番茄"、"打开微波炉"、"加热番茄"……**没有一个固定的"正确 token"可以读概率。** 你没法在模型 forward 里抓一个 P("把番茄放桌上"|记忆)，因为这个动作可能被 tokenize 成任意形式。

退一步说，即便正确答案可枚举，b_t 也只能在"答案揭晓"的步跳——看到告示、拿到钥匙。而 ValueProbe 问"能成吗"可以捕获更丰富的中间信号："番茄放进微波炉了"让把握从 0.6 涨到 0.8，虽然没有标准答案，但进展是真实的。

| 条件 | ValueProbe | ∆Belief |
|---|---|---|
| 正确答案可枚举（钥匙-门：4 个颜色词） | ✅ | ✅ **~1% 成本** |
| 正确答案不可枚举（ALFWorld：开放动作空间） | ✅ | ❌ 没法列候选 token |
| 中间步骤无"正确答案"概念 | ✅ "能成吗"始终可问 | ❌ b_t 只在答案揭晓时跳 |

**策略：两种都保留，真实数据上择优。** 钥匙-门等合成任务上 ∆Belief 几乎免费；ALFWorld 上退回 ValueProbe（13.9% 额外成本）。退路方案还包括 1.5B 小模型探针（~3%）或让 agent 决策时顺手输出把握值（零额外）。

### 3.3 跳幅 Δ_t

```
Δ_t = |V_t − V_{t-1}|,   V_{-1} = 0.5
```

- Δ 大 = 这一步让"能不能成"的判断剧变 = 该保留原文
- Δ ≈ 0 = 流水账 = 该狠压

V_{-1} = 0.5 是均匀先验：开局之前，啥都不知道，成败五五开。

### 3.4 三档分辨率

不是"留/删"两档开关，而是三级粒度：

| 档位 | 触发条件 | 输出 | 保真度 c |
|---|---|---|---|
| **FULL** | Δ 大，性价比高 | 原文一字不改 | 1.0 |
| **SUMM** | Δ 中等，预算不够展原文 | 抽取式短句，保留主干 | 0.6 |
| **MERGE** | Δ ≈ 0，或预算已耗尽 | "(此处 N 步例行操作已折叠)" | 0.3 |

**为什么需要中间档**：
- 两档是 0-1 背包，token 零头用不掉——剩余 token 装不下原文时长句只能整条丢，摘要能用这点零头保住主干
- Δ 是连续量，两档强二值化，在阈值附近的步被迫"全保或全丢"
- 保真度需要"在但不可靠"这个状态——只有三档才有 c = 0.6 这个中间值

### 3.5 固定 token 上限的贪心分配

```
起点：所有历史步 = MERGE，当前步 = FULL（不占历史预算）
排队：按性价比 = Δ / 长度 从高到低
逐个试升：先试 FULL，预算不够降试 SUMM，都不够保持 MERGE
Δ ≈ 0 的步：跳过低谷阈值 → 连排队资格都没有，预算宁可剩着
```

**两个关键设计**：
- 当前步不占历史预算——否则长观测会把历史关键步挤掉
- 性价比排序而非纯跳幅排序——30 token 的观测跳幅 0.15，不如换两个 10 token 跳幅 0.12 的短句

## 4. 阶段 B：软分组信用分配

压缩改变了 CA 的工作条件，CA 侧必须跟着改。

### 4.1 为什么必须改

| 压缩带来的变化 | 对 CA 的影响 |
|---|---|
| memory 不再是原始观测 | GiGPO 精确哈希（一字不差才同组）直接失效 |
| 压缩有损，且每步损失程度不同 | memory 的可靠度不均匀 |

### 4.2 三条改法

#### ① 软分组（替代精确哈希）

不硬分组，用 memory 的 phi 向量（每步压缩 memory 的语义编码，一次 forward 取 last-token 隐状态）的余弦相似度做核加权：

```
w_ij = exp((S_ij − 1) / τ)
```

- `S_ij` = phi_i 和 phi_j 的余弦相似度（1 = 完全一样，0 = 无关）
- `τ` = 核宽（默认 0.05），控制"多远算远"——τ 越小越翻脸不认人

phi 的关键时间线：每步存的是当时的压缩 memory 全文。步 2 在当下是当前步 = FULL，phi 拍的是当时的照片——后来被折叠了不影响它自己的 phi。

#### ② 保真度加权（★压缩独有的创新）

每个邻居的贡献再乘一个可信度：`w'_j = w_j × F_j`。F_j = 该步 memory 的保真度（按跳幅加权的档位分平均）。压得粗的步降权 → 防止把噪声灌进基准。

**保真度需要知道"哪一步落在哪一档"——这正是压缩过程的副产物。不做压缩的方法根本没有这个信息。**

#### ③ 动作反事实（借 PACE）

同一处境下按执行的动作拆开：`A_t = Q̂(s,a) − V̂(s)`。隔离动作专属的信用——"拿番茄"和"拿苹果"在同一个柜台前，必须比。

#### 优势计算

```
V̂(s) = 同一个软组里，所有邻居回报的加权平均
Q̂(s,a) = 同一个软组里，和你做了同一个动作的邻居的加权平均
A_t = Q̂(s,a) − V̂(s)
```

- A > 0 → 好动作，加分
- A ≈ 0 → 中性，无所谓
- A < 0 → 坏动作，扣分

### 4.3 四条臂的消融

| 臂 | 软分组 | 保真度 | PACE | 含义 |
|---|---|---|---|---|
| a_soft | ✓ | | | 纯软分组基线 |
| b_pace | ✓ | | ✓ | +动作反事实 |
| c_full | ✓ | ✓ | ✓ | 完整版 |
| d_conf_only | ✓ | ✓ | | 只加保真度 |

预期：b > a（PACE 有效），c > b（保真度加权有效）。

## 5. 数学骨架：信息瓶颈

本方法是信息瓶颈（IB, Tishby 1999）的一个实例化——新的不是发明 IB，而是把 Y 换成信用：

```
min  I(H;M)  −  β · I(M;C)
     token成本      信用信息保留
```

| IB 原版 | 本方法的对应 |
|---|---|
| 输入 X | 完整交互历史 H |
| 压缩表示 T | 压缩后的 memory M |
| 任务目标 Y | **信用 C** ← 换掉的就是这一格 |
| I(X;T)（要 min） | memory 的 token 数 |
| I(T;Y)（要 max） | memory 对信用分配还剩多少判断力 |
| β | token 上限旋钮——拧大 = 多留 token |

三层新意：
- CA 主线五篇都没用过 IB
- 用跳幅把 IB 抽象的失真落地成可逐步算的量
- 理论亲戚——Abel 的保价值抽象可改写为"压缩到什么程度，信用误差有界"

## 6. 与邻居的界限

| 论文 | 它做什么 | 与本方法的分界线 |
|---|---|---|
| **BiPACE** | cosine 软聚类 + PACE | 它横向合并状态空间，本方法纵向变时间轴粒度。**它亲口把压缩留作 future work** |
| **HGPO** | 层级分组（历史步数分层） | 承认压缩后层级分组 intractable |
| **GraphGPO** | 状态转移图 + Dijkstra | 最危险的碰撞：若用 MC 回报当价值，跳幅退化成"离终点多远" = GraphGPO。**排除 MC 回报的直接原因** |
| **∆Belief-RL** | 按信念变化做 intrinsic reward | 同一信号源，用途不同：它们做信用分配，我们做压缩信号。**第一个把 ∆Belief 用在 memory management 上** |
| **MemoPilot** | 多轮 GRPO 训记忆模型 | 轮级 vs 步级；自认长程压缩靠预处理非端到端 |
| **RGMem / Memora** | 多尺度粗粒化 | 壳一样（多分辨率），目标不同：它们为检索，我们为信用 |
| **PER** | TD-error 分配回放优先级 | 本方法的种子：同一原则从"复习谁"换成"压谁" |

## 7. 实验

> 五组实验分三个层级：**信号可信度**（①②）→ **压缩是否比不压好**（③④）→ **CA 侧改法是否必要**（⑤）。脚本均在 `experiments/` 下。

---

### ① 判据预检：信息量和信用相关性是不是两回事

**脚本**：`token_criteria_check.py`

**目的**：现有 prompt compression（LLMLingua / Selective-Context）以"保留信息量"为目标（罕见 token = 重要），我们的方案以"保留信用相关性"为目标（删除后 V_t 变了 = 重要）。**如果这两个判据高度一致，现成方法就够用了，整个方向降级成 related work 一句话。**

**过程**：对每条 ALFWorld 风格观测，逐 token 打两种分——
- 信息量 = −log p(token | 前缀)，一次 forward 全拿到
- 信用相关性 = |V(完整) − V(删掉这个 token)|，留一法逐个抹除、各问一次模型

算 Spearman 排序相关 + 两个判据的 top-5 token 定性对照。出口条件：|ρ| < 0.3 才往下做。

合成观测故意混入两类 token：杂物名（apple / saltshaker，罕见 → 信息量高，但与番茄无关）和关键动词（pick up / heat，极常见 → 信息量低，但决定成败）。

**结果**：两个判据的 Spearman 相关很低（|ρ| ≪ 0.3），top-5 重合率接近零。"apple"按信息量排第 1（罕见词），按信用相关排不上号；"heat"按信息量排不进前 5（高频词），按信用相关排第 1。

> ✅ 两个判据确实测的是不同东西。现有方法优化信息量，我们优化信用相关性——**设计动机不是空话。**

---

### ② 信号可信度检验：跳幅能不能预测真实重要性

**脚本**：`signal_check_test.py`（含 `--belief` 模式）

**目的**：整个方案的基石是"跳幅大 = 这步重要"。**如果这个前提不成立，后面全部白搭。** 用反事实干预量出"真实重要性"，再验跳幅能不能预测它。

**过程**：

1. **任务设计**：钥匙-门合成任务，四类步骤天然重要性不同——
   - 告示步（告知钥匙颜色）→ 抹掉必崩
   - 拾取步（捡起真钥匙）→ 抹掉必崩
   - 干扰步（捡起同色系假货）→ 抹掉无所谓
   - 填充步（走廊废话）→ 抹掉无所谓

2. **真实重要性定义**（不靠任何先验）：ΔAcc_t = 完整记忆的正确率 − 抹掉第 t 步后的正确率。用连续值（P(正确钥匙) 而非硬 argmax）避免二值化损失分辨率。

3. **三个对照打分**：跳幅必须同时赢过 random / recency / length 三者才算有独立信息。

4. **三种探针措辞**扫一遍（"能成功吗" / "掌握关键信息了吗" / "在正确轨道上吗"），选相关性最高的一版固定下来。

5. **`--belief` 模式**：用 ∆Belief 口径替代 ValueProbe——读 P(正确答案 | 前 t 步记忆) 的跳幅，不单独问"能成吗"。

**出口条件**：AUC > 0.7 且 ≥ 最强对照的 90%。

**结果**：

| 信号 | AUC | top-1 命中率 |
|---|---|---|
| ValueProbe·success | **0.905** | 88.9% |
| ∆Belief·abs | **0.839** | **100.0%** |
| 对照·random | 0.432 | 5.6% |
| 对照·recency | 0.617 | 41.7% |
| 对照·length | 0.938 | 100.0% |

> ✅ 跳幅 AUC 0.905，远超 random 和 recency。∆Belief AUC 0.839，top-1 命中 100%。

**两个重要发现**：
- length baseline AUC 0.938 比跳幅还高——但在合成钥匙-门任务里，长观测恰好包含更多关键信息。真实 ALFWorld 观测全是模板句，长度高度均匀，这个伪影会消失。
- ∆Belief top-1 命中 100%——对压缩来说，**最关键的那一步不错**比整体排序重要。

---

### ③ 压缩后的信用精度：压完还分得对吗

**脚本**：`credit_rank_test.py`（核心）、`sep_auc_test.py`（表示诊断）、`compress_test.py`（上游信息瓶颈）

**目的**：① 测了上游信号，⑤ 测了下游训练效果，**中间一环"信用分配"一次都没量过**。而"为信用而压"正是本方法区别于所有现有压缩方法的地方。

**过程**：

1. **任务 v3 版设计**（前两版被实测推翻后改了三次）：
   - 步 0：【告示】今天的钥匙是{颜色}的 ← 关键信息**只在这里出现一次**
   - 中间步：混入同色系干扰物 + 走廊填充，当前观测**只说颜色不说是不是钥匙**
   - 末步：面前一扇锁着的门——必须回头看步 0 才知道该拿哪个颜色
   - ⇒ 全部信用**都该落在"拿起真钥匙"那一步**

2. **四个对照臂**（同一批轨迹，只换喂进去的 memory）：
   - `full`：全量历史
   - `naive`：整段压成一句废话
   - `truncK`：只保留最近 K 步
   - `vtree`：我们的三档压缩

3. **前置诊断**（sep_auc_test.py）：压缩后的 embedding 能否区分"有钥匙"和"没钥匙"两种处境？对比 mean 池化 vs last-token 池化、扫 τ 敏感性。

**结果**：

| 指标 | 说明 |
|---|---|
| sep-AUC | 压缩后 0.93 > 全量 0.52~0.67 —— **压缩反而提升了处境识别** |
| 池化方式 | last-token 同/异处境差距 +0.401，远超 mean 池化 +0.013——差距 < 0.05 核加权退化 |
| 信用链条 | vtree 组的真钥匙步优势显著 > 0，full / trunc 组做不到 |

> ✅ 佐证动机二：冗余不仅占地方，还会淹没信用信号。**压对了地方反而让信用更清楚。**

### ④ 预算扫描：多少 token 够用

**脚本**：`sep_auc_test.py`（顺带）

**目的**：找出最小可用预算，确认方法不是靠堆 token 才赢的。

**过程**：在 sep-AUC 基准上扫四个预算档位（40 / 60 / 90 / 140 token），看曲线在哪拐弯。同时扫核宽 τ（0.01 / 0.05 / 0.1 / 0.3），看有效邻居数（权重的熵指数）随 τ 怎么变。

**结果**：预算 > 40 token 后边际收益递减，平台期 AUC ≈ 0.93。τ = 0.05 时有效邻居数落在 2~N/3 区间（适中）。

> ✅ 方法不靠堆 token——40 个 token 就够，再多是锦上添花。

### ⑤ CA 四条改法的消融

**脚本**：`ca_ablation_test.py`

**目的**：压缩之后，阶段 B 的各个改法各自值不值得留——**尤其是保真度加权**。前期 walkthrough 中保真度加权效果仅 1.438 → 1.439（几乎为零），本实验系统验它到底有没有用。

**四条臂**：

| 臂 | 软分组 | PACE | 保真度 | 含义 |
|---|---|---|---|---|
| a_soft | ✓ | | | 纯软分组基线 |
| b_pace | ✓ | ✓ | | +动作反事实（b > a？） |
| c_full | ✓ | ✓ | ✓ | 完整版（c > b？← **主问题**） |
| d_conf_only | ✓ | | ✓ | 只加保真度（拆开看贡献） |

**过程**：

1. 构造合成轨迹：钥匙-门任务，**当前观测不透露手里有什么**，必须从压缩后的 memory 推断。每个 seed 生成 G=24 条轨迹，四档预算轮换以制造保真度方差。

2. **三个前置诊断**（任一不过就别解读主结果）：
   - conf 方差：方差 ≈ 0 → use_conf 退化为乘常数再归一化 → 数学上必然无效
   - 子集样本数：有钥匙∧开门 / 有钥匙∧没开门 两个子集是否有足够样本
   - 分组质量：同处境 phi 相似度是否显著 > 不同处境（差距 < 0.05 → 核加权退化）

3. 四个 τ 扫敏感性，避免只在单一超参下报结论。

**结果预期**：

| 对比 | 预期 | 判读 |
|---|---|---|
| b − a | > 0 | PACE 有效，动作反事实必要 |
| **c − b** | **≈ 0 或 > 0** | ≈ 0 = 保真度无事可做（软分组已排除噪声），删掉更干净。> 0 = 有独立增量，保留 |
| d − a | > 0 但 c − b ≈ 0 | 保真度的作用被 PACE 吸收了，两者冗余 |

> ⚠️ 本实验的合格产出**包含"确认保真度加权没用"**。目标是搞清楚能不能少一个部件，不是自证有效。

### 合成数据说明

以上五组实验均在**合成钥匙-门任务**上跑。合成数据的作用是**快速验证机制原型**，不进论文当最终证据。论文证据来自后续在 ALFWorld / WebShop 真实轨迹上重跑的结果。

已知合成伪影：钥匙-门任务中 length baseline AUC 高达 0.938（带线索的观测恰好更长），ALFWorld 真实数据中观测长度高度均匀，此混淆预期消失。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 价值信号不可靠 | 实验①②已通过合成验证，下一步真实轨迹复现。∆Belief 为兜底选项 |
| 三档的中间档做不到 | 摘要器可插拔：先用零成本抽取式，质量不够换 LLM（已测 bs=8 85ms，占 4.3%） |
| 合成数据不可信 | 合成只作机制原型，不进论文当证据。论文证据来自 ALFWorld / WebShop 真实轨迹 |
| 保真度加权无增量 | 若实验⑤消融确认无效果，整条砍掉，方案反而更干净 |
| KV cache 复用接不上 | 退路：1.5B 小模型探针（~3%）或 agent 决策时顺手输出把握（零额外） |
| ∆Belief 在开放动作空间不可用 | 合成任务上 ∆Belief 先试，ALFWorld 上退回 ValueProbe；论文里如实报两种信号的适用条件 |
